Program Control Documentation
The Program Control component serves as the central coordinator between the User Interface (Team Member A) and the File Handler (Team Member B), and optionally the Cipher component (Team Member D for 4-member teams). This component orchestrates the flow of data and control logic for the application.

Responsibilities
1. Coordinate between UI and File Handler
   - Receive user commands from the User Interface component
   - Request file operations from the File Handler component
   - Return processed results to the User Interface for display

2. File Listing Logic
   - When no arguments are provided, request list of available files from File Handler
   - Format the file list with numbers (01, 02, 03, etc.) for display
   - Return formatted list to User Interface

3. File Content Retrieval
   - When a file number is provided as argument, map it to the actual filename
   - Request file contents from File Handler
   - Process the content (decrypt if necessary via Cipher component)
   - Return readable text to User Interface

4. Error Handling
   - Handle invalid file numbers
   - Handle file not found errors from File Handler
   - Handle decryption errors from Cipher component
   - Ensure graceful error messages are returned to User Interface

Component Interfaces

Input from User Interface 
- No arguments: Request to list all available files
- File number argument: Request to display specific file content
- Optional cipher key argument: Alternate decryption key

Output to User Interface 
- File list: Formatted string with numbered files (e.g., "01 filea.txt\n02 fileb.txt")
- File content: Decrypted readable text
- Error messages: Clear error descriptions for user

Interaction with File Handler 
- Request: getFileList()
  - Returns: List<String> of available filenames
  
- Request: getFileContent(String filename)
  - Returns: String containing file content (encrypted or plain text)
  - Throws: FileNotFoundException if file doesn't exist

Interaction with Cipher Component 
- Request: decrypt(String encryptedContent, String keyPath)
  - Returns: String containing decrypted content
  - Throws: CipherException if decryption fails or key is invalid

Class Structure

ProgramController
getAvailableFiles(): String
getFileContentByNumber(int fileNumber): String
getFileContentByNumber(int fileNumber, String alternateKey): String
mapNumberToFilename(int number, List<String> files): String

Key Design Principles
1. Single Responsibility: ProgramController only coordinates; it doesn't directly read files or perform encryption/decryption
2. Dependency Injection: FileHandler and Cipher components will be injected to allow for easier testing
3. Error Propagation: Errors from lower components are caught, wrapped with user-friendly messages, and propagated to UI
4. Stateless Operation: Each method call is independent; no session state is maintained

File Number Mapping Logic
- Files are numbered starting from 01
- Numbers are zero-padded (01, 02, ..., 09, 10, ...)
- The order of files matches the order returned by FileHandler.getFileList()
- Invalid numbers (out of range, non-numeric) result in error messages

Flow Diagrams

Scenario 1: List Files (No Arguments)
```
User Interface  ProgramController.getAvailableFiles()
            
                 ProgramController  FileHandler.getFileList()
                 
                 FileHandler returns List<String>
                 
                 ProgramController formats with numbers
                 
User Interface  Returns formatted string
```

 Scenario 2: Display File Content (With File Number)
```
User Interface  ProgramController.getFileContentByNumber(fileNum)
                 
                 ProgramController  FileHandler.getFileList()
                 
                 Map file number to filename
                 
                 ProgramController  FileHandler.getFileContent(filename)
                 
                 [If 4-member team] ProgramController  Cipher.decrypt(content)
                 
User Interface  Returns readable content
```

 Scenario 3: Error Handling
```
User Interface  ProgramController.getFileContentByNumber(99)
                 
                 ProgramController  FileHandler.getFileList()
                 
                 Number out of range detected
                 
User Interface  Returns error message: "Error: File number 99 not found"
```

 Error Handling Strategy

 Error Types and Messages
1. Invalid File Number: "Error: Invalid file number. Please use a number from the available list."
2. File Not Found: "Error: File not found or cannot be accessed."
3. Decryption Failed: "Error: Unable to decrypt file. Key may be invalid."
4. Empty File List: "No files available in the data directory."

 Exception Handling Approach
- Catch specific exceptions from FileHandler and Cipher components
- Transform technical exceptions into user-friendly messages
- Log technical details for debugging (if logging is implemented)
- Always ensure program exits gracefully with appropriate error message

 Testing Strategy (See test documentation for details)

 Unit Test Categories
1. File Listing Tests
   - Test with multiple files
   - Test with no files
   - Test number formatting (01, 02, etc.)

2. File Content Retrieval Tests
   - Test valid file number retrieval
   - Test with plain text (3-member teams)
   - Test with encrypted text (4-member teams)
   - Test with alternate cipher key

3. Error Handling Tests
   - Test invalid file numbers (negative, zero, too large)
   - Test non-existent files
   - Test decryption failures
   - Test FileHandler exceptions

4. Integration Tests
   - Test full flow from UI request to result
   - Test coordination between components

 Dependencies

 Required Components
- FileHandler (Team Member B): Must provide getFileList() and getFileContent() methods
- Cipher (Team Member D, 4-member teams): Must provide decrypt() method

 External Libraries
- JUnit 5 for unit testing
- Mockito for mocking dependencies during testing

 Implementation Notes

 Collaboration Points
- With Team Member A (UI): Define exact method signatures for ProgramController public interface
- With Team Member B (FileHandler): Agree on exception types and return formats
- With Team Member D (Cipher): Agree on decryption interface and error handling

 Design Patterns Used
- Facade Pattern: ProgramController acts as a facade, simplifying the interface to File Handler and Cipher components
- Dependency Injection: For testability and loose coupling
